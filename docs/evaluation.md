# 问答与清单评估记录

## 演示阶段已验证

自动测试覆盖以下行为，运行方式见项目 README：

| 场景 | 预期 |
| --- | --- |
| 演示资料中有“住宿” | 回答带资料标题与段落 |
| 演示资料没有“游泳池开放时间” | 明确拒答，引用为空 |
| 东校区本科新生提问 | 不引用西校区研究生通知 |
| 上传资料后停用 | 停用资料不再参与查询 |
| 资料过期 | 不将过期资料作为回答依据 |
| 同一通知上传新内容 | 新版本启用、旧版本停用 |
| PDF 上传 | 可提取文本并标记页码 |
| 住宿生生成清单 | 增加住宿事项；缺失字段标为待核实 |
| 模型回答引用无效编号 | 回退到资料摘录 |

## DeepSeek 在线验证（2026-10-11）

使用 `deepseek-flash` 和内置演示资料验证，密钥仅在测试进程的环境变量中使用，未保存到项目文件：

| 场景 | 结果 |
| --- | --- |
| 直接调用 DeepSeek 聊天接口 | 返回“连接成功” |
| 项目问答：报到需要准备什么材料 | 返回模型生成的演示答案，带 `[1]` 引用及“演示资料：报到说明 / 材料准备”来源 |
| 项目问答：游泳池周六几点开放 | 返回资料不足提示，引用为空，没有编造开放时间 |

以上仅证明演示流程可用；真实学校资料的准确率、引用有效性及不同条件下的表现仍需按下表评估。

## 接入真实学校后的评估表

先固定一批官方通知及其版本，再从真实用户问题中整理：20 个资料可回答的问题、10 个资料无法回答的问题、10 个不同校区或学生类型的清单场景、5 个过期或冲突资料场景。每个问题人工记录以下字段：

| 字段 | 记录方法 |
| --- | --- |
| 问题与适用条件 | 原问题、校区、学生类型、住宿情况 |
| 标准答案 | 由官方原文核对，不由模型生成 |
| 引用有效 | 回答所引段落是否真的支持结论 |
| 回答正确 | 材料、地点、时间及适用条件是否正确 |
| 拒答正确 | 资料不足时是否避免猜测 |
| 响应耗时 | 同一环境下记录接口总耗时 |
| 失败原因 | 检索遗漏、资料过期、版本冲突、生成错误等 |

正式评估前不要在简历中填写准确率。每次调整检索或提示词时，用同一批问题复测并保存结果。
